AI Workspace 0.7.0
个人 Windows GPT 聊天与开发工作台

开始使用
1. 关闭已打开的旧窗口，运行 AI-Workspace-0.7.0-Setup-x64.exe，按向导安装。升级保留原有账号、聊天、项目记录与恢复点，不会自动继续暂停的任务。
2. 打开“账号与设置”，通过 Continue with ChatGPT 完成官方登录与套餐授权，选择可用 GPT 模型。
3. 新建聊天，直接向 GPT 提问、讨论需求或让它解释代码。普通聊天不要求 DeepSeek 或项目文件夹。
4. 需要开发时，在设置中保存自己的 DeepSeek API Key；不要把密码、Cookie 或密钥发到聊天中。
5. 明确告诉 GPT“开始制作”“修改项目”或“开始开发”。GPT 会理解目标、设计和分派工作；若没有选择项目，它会保留开发要求，待你选择文件夹后自动安排。
6. 主聊天只展示用户与 GPT 的消息。右侧“执行详情”默认收起，可展开查看 DeepSeek、工具、测试和 GPT 检查的完整过程；重要操作仍需你审批。
7. GPT 可以亲自提供关键设计和代码，再交给 DeepSeek 落地与测试；执行遇到连续失败或多次调用工具时会中途接受 GPT 监督，不必等整个子任务结束。
8. 开发完成后继续在同一个聊天提问或提出修改要求。仅解释、讨论不会启动新开发；明确的后续修改会由 GPT 安排。同一聊天的不同开发任务可以在右侧切换查看。

0.7.0 新增：网页预览与自动浏览器验收
- 在聊天上方切换“网页预览”。普通 HTML 直接“打开网页”；有 package.json 的前端项目可“构建并预览”，自动执行项目自身的 npm run build，再打开 dist/build/out 等产物。可在位置设置中填写项目内相对文件夹和入口文件。
- 支持手动查看和操作、刷新、截图、电脑/手机尺寸、页面消息；宽屏可“并排聊天”。切回对话或打开设置时，网页不会遮住聊天或设置。
- AI 可以观察页面、读取可操作元素、点击、填写测试内容、选择下拉选项、滚动、切换尺寸、截图和检查页面内容。GPT 仍负责主聊天和验收，DeepSeek 负责执行；需要查看画面时 GPT 也能只读查看预览，不启动开发。
- 页面检查必须与当前项目文件对应，出现页面脚本错误或断言失败不能作为通过证据。需要构建的前端，构建后改动项目文件必须重新构建再验收。截图和检查记录保存在本机；用于当前任务的截图会提交给 GPT，以及支持图片的 DeepSeek 模型，继续使用已有账号与 API Key。
- 当前实测识图模型为 gpt-6.1-sol 和 deepseek-flash。没有已验证图像能力的 DeepSeek 模型使用页面文字和元素执行，截图仍交给 GPT；不自动切换模型或思考强度。
- 网页在单独的临时浏览器会话中运行，不继承软件账号或主应用接口。允许加载公网字体、CDN、图片及读取类 API；限制其他本地服务、私有网络、电脑文件、下载、文件选择、外部导航和公网写入请求。公网表单提交、iframe、需要登录的第三方业务操作不在本版自动验收范围内。
- 第一版支持静态页面和前端构建产物。需要 Node/Python 后端、数据库、本地 API、服务端渲染或开发服务器的项目，目前不能在内置浏览器中完成这些服务的整体验收；GPT 必须明确说明尚未验证的部分。没有通用 Windows 鼠标键盘控制。
- 构建沿用项目隔离运行、恢复点和审批规则；停止、关闭或电脑休眠会停止构建并保留已有项目记录。

0.6.0 功能：精简协作与连接恢复
- GPT 在聊天中已经给出完整、通过校验的任务包时，直接交给 DeepSeek；信息不足时仍先读取或澄清，没有任务包时仍保留独立规划。
- 你已同意合并最后一个子任务与整体交付验收。合并检查必须同时核对全部需求、实际文件和当前版本的真实测试；缺少整体完成说明或检查未通过时不能完成。在“账号与设置 → 协作与连接”可改回分开验收。
- 中途监督按连续失败或无有效进展触发；确实修改了文件或取得新的有效验证时重新计量，避免只因正常工作调用了多个工具就反复插入 GPT。每个子任务仍由 GPT 验收。
- GPT 内部任务与验收消息使用官方结构化输出约束，继续做本地结构和业务规则校验；拒绝请求会明确暂停，不再当成格式错误无限修正。
- 执行上下文过长时，将已完成的旧工具轮次整理为摘要，保留目标、最新决定、文件哈希及未完成的工具请求。完整记录仍保存在本地；重试提示不再挤掉 GPT 验收所需的真实工具证据。
- read_file 支持分段读取，默认最多 200 行和 24000 字符，并明确标识是否截断；edit_file 通过当前完整哈希与唯一原文锚点局部修改，全部匹配后才写入，修改前保存恢复点。
- DeepSeek 使用桌面系统网络通道，遵循系统网络与代理设置。连接过程分别诊断响应头等待、流停滞、服务限流、HTTP 错误、格式错误和输出上限；不输出密钥、服务端回显的项目内容或内部思考。
- 不再每次失败固定等待 8 秒。可恢复故障依次等待 1、4、10、30、60 秒，随后按至少 60 秒间隔继续，并遵守服务端 Retry-After。保持你原先“不设任务总时长和总尝试次数上限”的选择；手动暂停会立即停止后续重试。
- 余额不足、密钥无效、参数或证书问题会保留进度并暂停。单次输出到限会交给 GPT 改成较小任务或局部修改，不会把同一大段内容一直原样重发。不会自动换模型、降低思考强度或使用额外付费 OpenAI API。
- 单次连接在 45 秒未返回响应头，或流在 90 秒没有任何新数据时判为超时；正常数据和 keep-alive 会续延等待，不再用固定 3 分钟中断仍有进展的响应。
- 聊天进度显示具体等待原因和下次重试倒计时。设置中可“单独测试 DeepSeek”，不必先消耗一次 GPT 请求。
- 本次排查的两次固定短文字请求均正常返回。历史记录只保留了笼统提示，无法据此还原此前每次故障的具体原因；不能声称服务商已永久恢复。诊断未读取或发送你的项目内容，没有继续或修改原任务。

0.5.0 功能：自行管理模型思考强度
- 点击聊天顶部的模型名称，或打开“账号与设置”，在 GPT 和 DeepSeek 下方分别选择思考强度。选择后自动保存，按模型分别记住；切换回来会恢复这个模型之前的档位。
- GPT-6.1 Sol 和 GPT-6 Astra 可选：模型默认、低、中、高、很高、最高。GPT-6.1 Terra、GPT-6 Sol 和 GPT-6 Luna 还支持关闭思考。具体只显示已按官方文档核实的档位。
- DeepSeek Flash 和 V4 Pro 可选：关闭思考、低、高、最高。不把 DeepSeek 的档位强行对应为 GPT 的所有档位。
- GPT 的选择用于后续聊天、规划、监督与验收；DeepSeek 的选择用于后续执行。顶部模型旁显示当前 GPT 档位；执行记录会记录请求采用的模型和强度。
- 回复或开发正在进行时，请先暂停再调整。更高强度通常等待更久、用量更多，不代表所有任务都会更好；不支持的设置会提示，不会自动降低。
- 升级沿用此前行为：未指定 GPT 强度时用模型默认，未指定 DeepSeek 强度时关闭思考。没有替你选高档；你可以自行修改。未知模型暂时保留原行为，待核实支持档位后再开放。
- 这是独立应用自己的设置，不会同步更改 ChatGPT 官方 App 的设置。思考强度不等于展示模型的内部思考内容。

0.4.0 功能：GPT 提问、需求清单和阶段汇报
- GPT 遇到确实需要你决定的问题时，在聊天中显示提问卡片。支持单选、多选与补充文字，每次最多 3 题；不默认替你选择。也可以继续在普通聊天输入框回答或追问。
- 选项与补充文字会自动保存为本地草稿，关闭后可继续填写。提交后显示回答摘要；已被新问题替代的旧卡片不能再次提交。
- “需求清单”页整理目标、约束和验收标准。用户原话支持的要求标为已明确，GPT 的建议标为待确认；可以确认整份清单，或回到聊天补充修改。
- 只确认需求不会启动开发，也不能批准删除、安装、上传等重要操作。如果你已经明确要求开始开发，澄清问题回答完后，GPT 可以继续原先已授权的工作，不重复要求你说一次“开始”。
- 每个开发子任务实际经 GPT 检查后，在聊天显示“阶段验收通过”或“要求调整”卡片，展开可查看反馈。阶段通过不等于整个项目已经完成。
- 本版保留 0.3.1 的执行详情修复：长日志只在右侧区域滚动，聊天输入、关闭按钮与侧栏保持可用。

界面与进度
- 简洁黑白界面，正文 16px，支持浅色、深色和跟随系统。普通聊天默认收起开发详情。
- 开发时，聊天中的进度卡显示当前由谁处理、实际活动、已验收步骤和最近更新时间。点击“查看步骤”展开右侧计划；原始日志仍可单独展开。
- “全部步骤已验收”不等于任务已经完成；最终 GPT 核对结束前会继续显示最终核对。进度条只表示已验收步骤比例，不代表预计工时比例，不显示虚构的剩余时间。
- 等待审批时，操作确认会出现在聊天里，即使右侧详情没有打开也能看见。只有你能允许关键操作。
- 回复支持标题、列表、表格和代码块。代码块和消息旁可以复制内容；网页链接只在你点击后通过系统浏览器打开。
- 左侧可搜索聊天标题；在顶部重命名当前聊天，并导出这段聊天及关联开发记录。
- 输入框随多行文字增高；查看旧消息时，可点击向下箭头回到最新消息。900px 宽窗口使用可关闭的详情覆盖层。
- 本交付中的进度与排版预览使用明确标记的离线界面演示数据，不表示某个真实开发项目当时正在运行。

这是什么版本
这是可安装的个人集成测试版本。它包含真实官方 ChatGPT 授权和 DeepSeek API 接入代码。
此前 0.2.0 已在本机使用 ChatGPT Plus 官方连接与 DeepSeek API 验证“先聊天、再开发、再继续聊天”：两轮需求讨论不调用 DeepSeek；明确开发后 GPT 先读取项目并提供关键函数代码，DeepSeek 落地且通过固定 8 项 npm test 测试；GPT 验收后继续解释，未新增开发或 DeepSeek 调用。独立运行同一组测试也通过，测试和配置未修改。
上述 0.2.0 真实开发验收期间为改进监督机制暂停过，并从同一聊天和项目恢复完成。中途监督、文件夹检查期间不覆盖聊天、执行者问题由 GPT 处理等另有受控测试。完整原始记录见 AI-Workspace-聊天优先验收.json 与 AI-Workspace-验证记录.json。
此前 0.4.0 已通过真实 GPT 提问验收：官方现有授权下，GPT 生成两道选择题，接收单选、多选形式与补充文字后回复，并整理需求清单；纯讨论未创建开发任务，未读取 DeepSeek Key 或调用 DeepSeek。报告见 AI-Workspace-GPT提问真实验收.json。阶段汇报由实际验收事件生成，其卡片展示及返工、权限边界使用受控测试验证；该次 0.4.0 验收没有重新运行完整的真实双模型开发项目。
此前 0.5.0 已通过真实 GPT 低档与最高档请求验证，服务端回执分别返回 low 和 max；只消耗现有 GPT 套餐额度，没有读取 DeepSeek Key 或启动开发。首次验收器未能读取回执时，两次请求本身也均成功；修正验收器后再验证两次，共 4 次 GPT 请求。DeepSeek 思考模式的参数与工具连续调用通过受控网络响应验证，该次 0.5.0 验收未重跑真实 DeepSeek 任务。见 AI-Workspace-思考强度真实验收.json 和 AI-Workspace-验证记录.json。
本次 0.6.0 真实验收使用脚本新建的合成求和项目，未读取或继续你的项目与任务。最终流程用 2 次 GPT 请求及 9 次 DeepSeek 请求完成，约 125 秒；固定 8 项测试及独立复核通过，测试和配置未修改，无连接重试。开发期相同固定案例在按工具次数插入监督时约 206 秒；每种各 1 个样本，不构成稳定的速度、质量或费用保证。模型仍采用你的设置，没有为了测试自动降低思考强度。记录见 AI-Workspace-协作真实验收.json 与 AI-Workspace-协作观察.json。
真实案例只能证明已验证的行为，不代表所有项目或运行环境都覆盖。尚未对同一任务进行 GPT 单独执行与双模型执行的成本、质量对照，不能保证固定节省比例或完全没有质量差异。
Node 默认测试子进程模式在当前 Windows 隔离环境可能等待不返回；验收项目在模型开始前固定使用支持的 --experimental-test-isolation=none 模式，独立复核在隔离环境外使用默认 node --test。兼容限制及旧版首次结果保留在记录中。
测试机为 Windows 11 x64（10.0.26300）；Windows 10 尚需另机验证。

你确认的运行规则
- 只在自己电脑使用，Windows 10/11 桌面界面，中文说明。
- 编程为主，覆盖网站、Windows 软件、Python 工具及已有项目。
- GPT 默认负责聊天，开发时负责规划、关键实现、分配与检查；DeepSeek 按需执行；本地引擎负责权限和实际工具调用。
- 尽量自主，一次执行一个任务，其余排队。
- 运行时间、返工次数、DeepSeek 使用费用不设上限。
- 关闭窗口或电脑休眠时暂停并保存；重开后点击继续。
- GPT 授权不可用或 Plus 额度不足时暂停，不自动改用额外付费 OpenAI API。
- 修改前保存文件恢复点；删除已有文件必须审批。
- 项目依赖可以自动安装；系统开发工具安装必须审批。
- 不自动上传代码、创建远程仓库或发布。涉及这些操作时请求你介入。
- 不模拟鼠标、键盘或操作其他软件。
- 当前版本必须通过相关运行检查，并经 GPT 验收后才能自动标记完成。

权限与执行方式
文件工具校验相对路径、项目边界、保留设备名、数据流路径与链接。不能把当前目录当作隔离边界。
普通命令在 Windows AppContainer 中运行。应用先建立项目的执行副本，在其中运行命令，核查文件变化，再同步到原项目。
已有文件的删除在同步前逐项审批。命令中断时不会把未完成副本直接当成项目成果。恢复时不会盲目重放结果未知的操作。
长命令会交还进度给执行 Agent，由它查询退出码和输出；发现异常等待时可以停止单条命令并诊断，不需要取消整个任务。
Node 内置测试的默认子进程模式在当前隔离环境可能等待不返回；可使用当前 Node 支持的 test-isolation=none 参数在同一隔离进程运行相同测试，实际方式必须在交付中说明。
如果其他编辑器在命令运行时改动了原项目，应用会停止同步并要求重新检查，以保护你的修改。
Node、npm、Python、Git、PowerShell、.NET 使用本机已经安装的工具。应用可制作独立的只读工具副本以支持隔离环境，因此初次运行和大型项目可能花较长时间，也需要额外磁盘空间。
Python 工具副本包含必要的标准库与 pip，不直接加载本机全局第三方包。项目所需的第三方包由依赖安装工具安装在项目内。
项目里的链接或连接点会被拒绝；可改用文件的普通副本。
普通命令不能联网。项目依赖安装使用专用联网工具：npm 禁用安装生命周期脚本，pip 仅安装二进制包到项目 .aiw-python 目录。
少数需要安装脚本、图形交互、系统服务、特殊硬件、其他目录或网络的项目，需要你介入处理相应环境，不能保证所有程序都能在隔离环境中执行。
受支持的系统工具可通过明确审批，使用 winget 安装 Node.js LTS、Python 3.13、Git 或 .NET SDK 10。该系统安装动作可能触发 Windows 自己的权限确认；若没有 winget，则会提示手动准备工具。

账户和数据
ChatGPT 使用 OpenAI 官方 Sign in with ChatGPT，不读取其他应用的登录文件，不抓取 Cookie，不索要密码。
使用 OpenAI Sign in with ChatGPT DevKit local SDK，授权、加密存储和续期代码保持原样；为支持思考强度，本应用扩展请求类型和序列化代码，传入官方 reasoning.effort、严格 text.format 结构，并将拒绝响应作为终止错误处理，修改标记与同许可声明见 vendor/siwc/AI-WORKSPACE-CHANGES.txt。凭据通过 Electron safeStorage 在 Windows 上加密；应用界面只能取得账户状态，不能取得已保存的令牌或密钥。
OAuth 自动续期、账户切换、权限校验和退出撤销由官方组件处理。请在 ChatGPT 设置中管理应用的套餐使用权限与限额。
应用账户、任务库、工具缓存和恢复点位于：%APPDATA%\AI Workspace
预览版与安装版使用同一数据位置；安装包升级会保留记录。卸载默认不删除这些数据。
任务记录和恢复点保存在本地；完成任务所需的提示词、代码片段、工具输出会发送到相应模型服务。本软件需要联网，并非离线模型。
DeepSeek 费用以服务商实际账单为准。应用显示服务返回的 token 用量，可手动配置每百万 token 单价进行估算；异常中断的调用可能没有完整的用量返回。
GPT 额度请通过“管理套餐用量”打开 ChatGPT 查看；应用不会伪造一份独立额度或切换账户规避限制。

常用操作
Ctrl+N：新建聊天。
Ctrl+K：搜索聊天标题。
Ctrl+B：折叠或展开聊天侧栏。
Esc：关闭开发详情（账号设置打开时则关闭设置）。
Ctrl+,：账号与设置。
Enter：发送；Shift+Enter：换行。
聊天页签：对话、需求清单、用量；有关联开发任务时还可查看项目文件和恢复点。
暂停任务后可在文件页编辑文本，保存前自动建立恢复点。
已完成任务的文件被手动修改或恢复后，会进入待重新验收状态。
右上角可打开项目、导出完整任务记录、显示或隐藏任务面板。

从源码运行
需要 Windows x64、Node.js 22.12 或更新版本，以及 Windows 自带的 .NET Framework C# 编译器。
在本源码目录运行：
  npm ci
  npm run build
  npm start

检查与打包
  npm run typecheck
  npm test
  npm run test:desktop
  node scripts/test-polish.mjs
  node scripts/test-decisions.mjs
  node scripts/test-reasoning.mjs
  node scripts/test-cooperation.mjs
  node scripts/test-execution-layout.mjs
  npm run package
  node scripts/test-packaged.mjs
  node scripts/test-decisions.mjs --packaged
  node scripts/test-reasoning.mjs --packaged
  node scripts/test-cooperation.mjs --packaged
  node scripts/test-execution-layout.mjs --packaged
联网安装测试需先设置 AIW_NETWORK_TEST=1，再运行 npm test；它只安装公开测试包，不调用付费模型。
Python 隔离运行测试需设置 AIW_PYTHON_TEST=1；它使用本机已安装的 Python，不会安装系统工具。
新版合成项目协作验收：node scripts/run-live.mjs --cooperation。它只创建并使用脚本生成的独立求和项目，调用真实两模型并执行固定 8 项测试，不读取或继续你的项目与任务；会消耗现有模型用量。
只含固定文字的连接诊断：node scripts/run-live.mjs --diagnostic。它比较两种网络通道，不发送项目内容，会进行两次简短的 DeepSeek 请求。
真实 GPT 思考强度验收可运行 node scripts/run-live.mjs --reasoning，分别使用低与最高档请求并核对服务端回执；需要本软件中已有官方授权，会消耗 GPT 套餐额度，不读取 DeepSeek Key。
真实 GPT 提问验收需在本软件中已完成官方授权，再运行 node scripts/run-live.mjs --questions；它使用现有 GPT 额度，只进行讨论，不读取 DeepSeek Key。其余默认测试使用独立测试数据，不调用付费模型。
安装包默认生成在项目上两级的 work/final-release 目录。首次构建会下载 Electron 和 NSIS 构建组件。
如果把源码目录单独移动到其他位置，可修改 package.json 的 build.directories.output 指向期望的构建目录。

源码结构
src/core/conversations.ts：GPT 持续聊天、只读项目分析、明确意图调度、结构化任务包直接交接、同聊天继续与对话压缩。
src/core/decisions.ts：问题与回答校验、需求清单来源和状态、原开发授权保留。
src/core/engine.ts：规划、执行、验收、返工、任务排队、连接退避、合并最终验收、暂停与审批。
src/core/deepseek-stream.ts、model-errors.ts：DeepSeek 流式解析、活动超时、诊断与重试分类。
src/core/task-context.ts、structured-output.ts：工具上下文整理、有效证据与官方结构化输出约束。
src/core/tools.ts：模型可请求的工具及参数校验、结果去重。
src/core/files.ts：项目边界、文件恢复点、内容校验。
src/core/runner.ts：隔离副本、开发工具、依赖安装、结果同步。
native/SandboxRunner.cs：Windows AppContainer、进程树和句柄隔离。
src/core/providers.ts：ChatGPT 与 DeepSeek 连接、思考参数与执行者工具思考上下文。
src/reasoning.ts、src/core/settings.ts：已核实的模型档位与设置校验。
src/core/store.ts：SQLite 本地任务与执行记录。
src/main.ts、src/preload.ts：桌面进程与受限的界面桥接。
src/ui：聊天界面、Markdown 排版、真实进度状态、提问卡片、需求清单、阶段汇报、项目文件、恢复点、用量与设置。
vendor/siwc：官方登录组件，来源提交 0a36fefeb913055c8c7a1a29b63d82b96b2e841a；请求类型、结构化格式和响应处理的本地扩展见随附修改说明。
